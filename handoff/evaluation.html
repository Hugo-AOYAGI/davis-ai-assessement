Buildability agent: evaluation

v1The agent looks at the scanned zoning plan and guesses by eye where the site is.
v2A tool draws the parcel outline on the zoning plan, with an estimated registration uncertainty.

v1 and v2 were run with Claude Haiku 5.5 (lower-cost configuration). v2 was also run with Claude Sonnet 5.5 (larger, about 20× the price) for every agent.

How we measure

70 test cases, with expected answers source-checked by model workers against cadastre, the archived 2021 zoning map and PLU regulation; this is not human sign-off. 20 cases test each step on its own, 10 test the full study.

MetricWhat it meansHow it is computed
FactOne expected value in the output: a parcel id, a zone code, a maximum height, a setback, a rule of the regulation.451 facts over the 70 cases. Ids and codes must match exactly; numbers within a small tolerance; lists must hold the expected items and none of the excluded ones.
CitedThe value is backed by its source.When the fact comes from the regulation, the output must cite a page of the PDF that holds the rule. The quote is checked automatically against the page text.
Facts rightThe share of expected facts answered correctly, with evidence where required.grounded-correct facts ÷ facts expected
Key factA fact a study cannot get wrong: parcel, zone, verdict, footprint, height…193 of the 451 facts are marked key in the test case.
Forbidden claimA known trap, e.g. quoting the rules of the wrong zone.A judge model (Claude Sonnet) reads the output and answers yes or no for each forbidden claim. It also decides whether a regulation note states an expected rule.
Case passedThe benchmark's critical-fact and forbidden-claim criteria passed.Every key fact correct, cited where evidence is required, and no forbidden claim. One miss fails the case. cases passed ÷ cases
CostWhat the agent spends on model calls.Tokens of every agent call × list price. The judge is not included: it grades, it is not part of the product.
TimeHow long one case takes.Wall time from the request to the final answer, averaged per case. Cases ran 4 at a time.

One run per configuration on a small benchmark; differences are descriptive, not a statistical significance claim. The judge was not calibrated. Case passing does not independently require every ambiguity flag, citation diagnostic or envelope consistency check. Geographic facts have no regulatory-text citation requirement.

Takeaways

  • The v2 configuration improved zoning in these runs: 2 to 13 cases passed with Haiku. Parcel overlays, image rendering and image-context pruning changed together; this does not isolate one cause.
  • The Sonnet configuration passed three more cases: it cost roughly eight times as much overall, while average full-study latency was about half. Repeated runs would be needed to assess stability.
  • Same failures on both models: thin legend items on the plan (flood zone, reserved land), the choice of neighbouring parcels, and one crash in the envelope drawing (e06).
